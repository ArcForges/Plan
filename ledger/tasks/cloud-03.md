## Incident and recorded non-fixes

- **Secret scan.** The first heads failed the history secret scan (gitleaks, all branches) and also made the manual-dispatch scan on main fail while the branch existed. Cause: identifiers containing key or token next to high-entropy values (a vector field `keyHex`, `scopeKey`, a source file named `...SortKey.cs` in the release profile, a test constant naming a token, an `IsKey("...")` literal). The identifiers were renamed and the branch squashed; no rule, regex, path or allowlist was changed or added.
- **Not fixed (reviewed, documented):** a module plan could still name a bookkeeping table (`platform_schema_state`, `platform_migration_receipt`, `platform_backfill_checkpoint`) because the ownership rule accepts any `platform_` table; review is the only stop. The binding and REST clients map result rows with `Object.values`, so a hand-written backfill page query must alias every column distinctly (the runner's own queries do). The runner identity of two migrators that share one is still separated by the fence.
