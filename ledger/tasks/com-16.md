## Owned elsewhere, limits and surviving findings (each with its owner or prerequisite)

- **Production wiring gap (documented in `docs/entitlement-resolver.md`, "Not covered here").** The host binds the plan port factory to the signed executor only when the foundation configuration provides the executor and the recovery generation (the proof configuration today), and nothing supplies `IEntitlementDefinitionSource` (the configuration activation task does). Until a composition supplies both, none of the module's services is resolved; no route, method policy or request changed. The Commerce participation in the purchase unit of work is CLOUD.63.
- **Term, status and release owner admissions are later tasks.** The store appends service terms (complete rows), term actions, workspace status facts and definitions activations through its own write path, and feature releases through a separate global append; COM.11 (terms), trust and safety (status facts) and configuration (feature releases) publish the ports that call them. COM.16 publishes no port for them.
- **Known coverage gap (Low, reviewer-reported, optional follow-up).** `ModulePlanPort.Owned` compares the first segment of the plan id exactly, but `OwnershipIsTheExactFirstSegmentOfThePlanId...` asserts only that some exception is thrown, and all eight variants are also absent from the plan manifest, so replacing the rule with `Contains(owner + ".")` survives the managed suite. The code is correct (with owners that contain no dot it is equivalent to the earlier prefix test); the fix is to assert the exception message of the ownership branch. Not done in this task because the approved head was not to move.
- **No workspace check in the SQL of the revocation and term-action inserts.** A `WHERE` on an `INSERT ... SELECT` would drop the row silently and let the commit succeed without it. A revocation is admitted only for a grant in the workspace's own loaded set (`UnknownGrant` otherwise) and COM.11 owns term-action admission; the load side is pinned by a two-workspace test.
- **Round trips and replay cost.** A load is about eleven plan calls (the revision twice, the snapshot, one page per record kind, the feature releases) and every issue, revoke and refresh loads first; the 2000-record history bound and the single authoritative clock assumption of COM.05 stand.
- **The grant port carries no caller authorization by design;** who may call it is each caller's concern and CLOUD.63's.
- **Substitutes still in use:** none registered. The COM.05 in-memory store remains a test substitute for fast resolver tests and is no longer the only store proof.
- **Untested coverage:** a deployed Cloudflare D1 and its REST or binding `batch` atomicity at production load (the `RES-cloud-deployment` lease was not taken and no deployment was observed; CLOUD.70 owns the deployment migration step that will apply migration 0024); real D1 limits and latency for a large commit; the workerd run at the final head by a reviewer; the Native AOT binary executing the store (it is compiled with warnings as errors in CI, not run); any provider event, checkout or payment path; client behavior on the distributed snapshot (COM.06).
