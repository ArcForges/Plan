### Live scenarios

**First run (before the fix), 08:07:28Z to 08:07:56Z.** `node eng/verification/foundation-live.ts` against `https://proof.arcforges.com`, signed with the local operator key, stopped at the R2 scenario and wrote no evidence file, so readiness, exact values, guard rollback and session/CSRF/revoke have no record from it (their assertions did not fail). **Diagnosis of the failure.** The PUT status was not captured in the first reply (the reply carried one boolean). The cause is inferred from the code and was not observed directly: the facade wrote with `onlyIf: { etagDoesNotMatch: "*" }`, which on an existing key returns before R2 evaluates the checksum, so a same-length body with different bytes was answered 200 `existing`. The offline fake already modelled the conditional-first order, but the only offline mismatch test used a fresh key. The decision (task text: a bounded signed PUT with a server-verified SHA-256) was that bytes not matching the declared hash must be refused whether the key exists or not, so the facade was fixed (Cloud PR 38: bounded body read, length and SHA-256 verified by the facade before any write) and the scenario now checks both an existing and a fresh key and reports the PUT status of each.
