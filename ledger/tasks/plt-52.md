## Limits and untested coverage

- The evidence is the offline simulated-consent-state suite only: Linux from the hosted run, Windows from the local run above, with a manual clock. There is no UI (the shown-in-full display, the consent surface and the verbose-session indicator belong to the shell), no real telemetry exporter or backend, no platform crash-capture hook, no macOS run and no product host. No GUI, live-service or installed-consumer validation was performed or is claimed.
- Metrics export gating is documented and host-owned; it is not implemented or tested here.
- Revocation is guaranteed at the hand-off to the host transport only. `Revoke()` does not call the transport, so a host's own queues and the PLT.50 `TracePolicy` buffer must be purged from `TelemetryConsent.Changed`; that wiring is documented and not integration-tested. A report upload that has already started is neither awaited nor cancelled by a revocation (no upload starts after `Revoke()` returns). `Changed` carries no state: a re-grant landing between a revocation's state change and its `Changed` event would make a handler that checks `IsGranted` skip the purge (reviewer note B).
- "Shown in full" is enforced as an order (no approval before `Preview()` was called) plus byte identity (the sent bytes are the previewed text); it is not proof that a UI displayed the text, and any code in the process can call `Grant()` or `Approve()`.
- The consent file is unauthenticated: a malformed record is Absent, but any process of the same user can write a well-formed `granted` record, which is honoured at the next start. The local log is not encrypted and the directory has no cross-process lock.
- The 256 KiB report log cap is unit-tested only through `FitToByteLimit`. No test drives `CreateReport` with an oversized log, so removing that call in `BuildDraft` leaves every test green; no end-to-end test of the cap is claimed.
- Open items for PLT.53: `ArcForges.Observability.Desktop.TelemetryConsent` shares its name with the static `ArcForges.Observability.TelemetryConsent`, so a file importing both namespaces must qualify one (the name is fixed by the merged RP-10 rows, so a rename needs a planning change); `InternalsVisibleTo` for the test assembly and the null-by-default internal `BeforeGrantCommit` test hook exist on the production type and should be re-confirmed when PLT.53 decides what is published; package admission and real-integration acceptance are PLT.53's.
