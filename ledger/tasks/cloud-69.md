The host applies the same validation, binds a `CorrelationContext` to each admitted call (stated value, else the trace id of a strict single `traceparent`, else a new identity; host span a child of the Worker's) and builds `ResponseMeta` and `ArcError` from it; the proof probe replies use them. The job wake message carries `correlationId` and `causationId` in its closed key set (a wake queued earlier still parses), a continuation keeps the correlation and is caused by the previous wake event, and the private signed job-slice body carries both, which the host requires as canonical UUIDs, echoes and stores in the `job.slice` outbox payload. The correlation never takes part in credential, Origin, CSRF, session, owner or generation decisions. Lease, fence, retry and backoff semantics are unchanged.
