- Outcome delivered (ArcForges.Assistant.Abstractions, one new file each for the lifecycle and the draft port): `AssistantLifecycle`, the reusable `IHostLifecycle` for one composition; `AssistantView` (one per window); `AssistantWorkHandle`; `IAssistantDraftStore` and `AssistantDraft`; the optional `IAssistantRemoteLink`; `AssistantLaunchReport`. Launch creates the one session through `AssistantHost.Create`, recovers durable drafts and observes Cloud reachability, and neither launch nor save consults Cloud (an absent or throwing link is reported as unavailable). Each view has its own draft and a view-scoped cancellation token; closing one saves its draft and cancels only that view, leaving the session, other views, local work and Cloud work untouched; a view that cannot save on close stays registered and refuses shutdown. The session and services are released once and last by `DisposeAsync`, which never throws and reports what it could not save or dispose. Shutdown saves drafts, asks local work to checkpoint (false, throwing or hanging means refusal), never blocks on or cancels Cloud-only work; `RequestStopAsync` and `OnProfileChangingAsync` use the same rule. Every store call and checkpoint is raced against a bounded timeout. Disposal is terminal, including against an in-flight launch. After an unknown-effect save (timeout, cancellation, untrusted acknowledgement) or a revision mismatch the view re-reads the store: its own earlier write, or a vanished draft, becomes the new baseline, while a foreign write stays a surfaced `conflict.revision_mismatch`.
