### Egress integration (blocked, not done)

No sink maps the delivered PLT.41 `EgressAuditRecord` into the audit store, and `EgressDecisionFact` remains an audit-owned mirror with no compile-time link. The mapping cannot be written without inventing data. The exact mismatches between `EgressAuditRecord` and the typed audit event (`AuditEvent` with `AuditEgressDetail`):

1. **Effective risk.** The audit event requires R0 to R4. `EgressAuditRecord` carries none (the egress authority does not take effective risk as an input, and the step-8 port `AuthorizeEgressAsync(request, destination)` does not pass it).
2. **Resource identity.** The audit resource is a typed Guid. The record's resource is an opaque string id with a string revision, which has no lossless Guid form.
3. **Authority identity.** The audit detail requires an authority object Guid and a committed positive revision. The record carries an `EgressAuthorityKind` and a free-text authority reference (plus grant issuer and generation strings).
4. **Data-class vocabulary.** The audit classes (canonical user data, managed asset, external reference, derived data, device-local state, secret, ephemeral data, operational data, audit or commercial) are not PLT.41's tiers (public, diagnostic, workspace content, sensitive content, secret material), and there is no agreed translation.
5. **Refusals before classification** (malformed or undeclared destination, classifier unavailable, unclassified content) have no destination class and, for a malformed destination, no canonical destination. The audit detail requires all of them, so these decisions cannot be stored as typed.

Also not mapped one to one: the specific `EgressReason` collapses to the audit's closed reason set, and PLT.41 documents that a timed-out audit write may land later as `Authorized` beside a refusal, which the intake must accept.

**Unblocking planning decision (owner: Architecture Owner), as described by the reviewer and confirmed by this follow-up.** Decide and record the following, then repair the Design text and the PLT.44 and PLT.41 scopes accordingly: (a) a data-class translation table between PLT.41's vocabulary and the audit's (or an audit vocabulary extended with PLT.41's tiers); (b) carriage of effective risk on the egress audit record (a PLT.41 or Security change, because the PLT.44 write scope does not include Security); (c) either Guid plus committed-revision identity for the resource and the authority on the PLT.41 record, or a relaxed audit shape that stores a bounded string identity and the authority kind and reference; and (d) a relaxed audit shape for denials and pre-classification refusals (optional destination, destination class and data class when the decision refused before they were known). The PLT.44 task text ("preserving ... authority ID/revision, risk") assumed a PLT.41 fact that the delivered PLT.41 does not produce. Until that decision lands, completion is not possible: PLT.44 must not complete on the lease integration alone.
