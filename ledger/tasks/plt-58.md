## Implemented production behavior

- `DesktopObservabilityHost.Open` actually opens the bounded local diagnostic store and durable consent, attaches `TracePolicy` to the selected activity sources, composes the real OTLP exporter and consent-gated signal sink, observes only the closed metric catalogue, runs periodic collection and supplies actual filesystem readiness. Opening the host never grants consent. The real collector endpoint and credential owner are explicit caller configuration.
- `OtlpHttpExporter` sends bounded, sanitized OTLP/HTTP JSON over real HTTPS sockets. It refuses redirects, cookies, URI credentials and unmarked or stale collection epochs. Queue count and byte budgets include the in-flight record. There is no disk spool or unbounded task-per-record queue. Encoding is explicit and Native AOT compatible; invalid/non-finite metric values and uncontrolled dimensions are refused.
- Consent withdrawal advances the collection epoch before persistence and immediately purges queued records and trace retention, cancels in-flight HTTP, credentials and retry backoff, and prevents a rapid regrant from admitting old records. Manual activity listeners must call the write-once `OnSpanStarted` at the actual collection start; unmarked revocable spans are refused. Direct `SignalEmitter` composition captures the actual `ITelemetryEpochSource` before materialization and retains the immutable epoch through transport handoff. An epoch is internal provenance, never an exported user label.
- HTTP delivery has bounded deadlines and attempts, classified terminal authorization/client responses and retryable transport/429/502/503/504 failures, bounded retry-after and jitter. Oversized, malformed or partially rejected collector responses are failures. An opaque credential is acquired fresh per attempt, never enters telemetry, and late credentials from an uncooperative owner are disposed. At most one such credential call can remain outstanding; cancellation cannot forcibly terminate foreign code.
- Shutdown is cached and idempotent, stops new admission, cancels producers, drains within the configured deadline, then cancels remaining work. `DependencyHealthMonitor` serializes refreshes, bounds each independent dependency and refuses fabricated health; at most one uncooperative check per dependency remains outstanding. `DiagnosticDirectoryProbe` tests an actual existing directory with a unique delete-on-close file. Collector health follows actual delivery observations and expires to Unknown; no successful test fake is used to claim production availability.
- No project/dependency coordinate, central version, package identity, lock or package catalogue changed. Existing admitted Observability package identities are preserved. Supporting changes are owned append-only API/provenance bindings and accurate composition documentation.
