## Untested coverage and known limits

- **A bound child process that has gone** is not covered by a test through the adapter (the reviewer's surviving mutant). The Security README says a session whose parent or bound child is gone stops vouching; that holds by the launch authority's own checks (PLT.10 observed a killed child on Windows), not by a PLT.38 test, so treat that sentence as unproven here.
- **Transport boundary strength.** No child process, OS stream, peer OS identity, second account, Linux or macOS real-process run. The binding records the assurance `LaunchClaimWithSecretProof`; it does not run the registration or bootstrap proof exchange (PLT.11) and its bound caller instance is null until PLT.11 supplies one.
- **Source defaults.** A host `ISensitiveOperationSource` that answers `None` (the enum's zero value, for example a stub returning `default`) disables step-up for every capability below R4; the pipeline cannot tell that from a capability that is not a sensitive operation. This is a host trust boundary, stated in the README.
