# Entry prompts

Paste one of these prompts into a new session and replace the angle-bracket arguments. Together with [arcforges-implementation.md](arcforges-implementation.md) each prompt is complete. Several sessions may run at once: claims keep them from colliding, and everything a session needs to resume is in the claim, lease and role records, the pull requests and the ledger, never in an earlier conversation. Give every session its own worker name.

Every prompt ends with the same policy line; it restates [execution-policy.md](execution-policy.md) and changes nothing in it.

## Worker

```text
Act as ArcForges delivery worker <worker name, unique to this session>. Scope: <any ready task | task IDs or rows copied from list.md | lanes | repositories>.
Read C:\MyFile\Projects\Plan-B\arcforges-implementation.md completely and follow it, including execution-policy.md. Work only from the authoritative state reported by python C:\MyFile\Projects\Plan-B\tools\delivery.py (ready, status, show). First resume your own claims with status --worker <name>. Then repeatedly select work in the order the procedure gives and within the scope, claim it with the tool, and take its self-contained prompt from the lane file under C:\MyFile\Projects\Plan-B\tasks\. Verify facts, finish research and decisions, establish one complete ordered plan, then execute continuously in a retained worktree on branch task/<key>. Record every handoff checkpoint with the tool, request review, merge through the repository's integration role at the reviewed head, record the ledger and the final claim state, then take the next work. While your task waits on review, CI or a merge queue, review, integrate, take completion follow-ups or start another ready task. When the scope has nothing available, report what it waits on and stop.
No macOS CI, hosted device/emulator/GUI/browser E2E, live service/inference, installed-consumer or public-release upgrade tests. No routine public artifact downloads, repeated archive/hash comparison or post-merge runtime cycles. Keep necessary Windows/Linux compilation/AOT/packaging, targeted offline/static/security checks and required signing/licence/lock integrity. Runtime tests are affected-scope local opt-in using existing environments, once; no validation-driven toolchain reinstall; one CPU-heavy local build per workstation through the build slot. Use normal networking and no wsl.exe wrappers; on a network failure, stop and report the operation. Do not create tags or republish solely to verify. Review every PR and fix findings; merge after retained applicable CI is green, and docs-only PRs without CI after review. Keep branches and worktrees. The user's latest instructions determine whether to start, continue or stop.
```

For specific tasks, put the task IDs (or the rows copied from `list.md`) in the scope. The worker executes each one that is ready, reports the others with their unsatisfied prerequisites, and takes each remaining task as soon as it becomes ready, so a table of related tasks can be pasted as is.
