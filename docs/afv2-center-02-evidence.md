# AFV2-CENTER-02 evidence

## Scope and candidate history

[Node PR 113](https://github.com/ArcForges/ArcForges/pull/113) implements six owner-local CenterControl methods and CLI commands. The durable receipt uses the existing owner epoch and command identity. Restarted accepted work stays unknown without fabricating a current connection as the original response. The protected Link loads before CenterControl accepts work. Explicit Disconnect disables outbound communication, retains the exact protected credential and clears the live enrollment projection. Local Run and private data lifetimes are independent.

[Cloud PR 167](https://github.com/ArcForges/Cloud/pull/167) adapts the real existing enrollment and PostgreSQL authority to a separate V2 outbound channel and owner DeviceService inventory/revocation. The V2 write verifies current device/key/session/epoch and Hub lease under one transaction. An enrolled device remains owner-visible before its first V2 connection, with offline presence and no unconfirmed capabilities. The scoped Worker upgrade entries reuse the existing quota and surface decisions. No production surface switch is changed.
