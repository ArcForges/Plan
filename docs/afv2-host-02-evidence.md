## Provider scope

Paddle Billing v1 is pinned on API requests. The webhook notification destination has its own v1 selection, and actual provider and browser payment-page qualification remain AR-10. Webhook ingress is bounded and passes the original signed bytes to Go. The Center validates the receiver secret, timestamp and exact resource before applying provider authority. Exact supported receipts commit before the 200 response. Authenticated unsupported notification kinds have an effect-free acknowledgment. The Worker strips other request and response data from this provider route.

Paddle does not document a general caller-provided idempotency key for create operations. One durable local purchase and original checkout claim precede external create. An uncertain response is reconciled through documented API origin, a bounded persisted claim window and exact opaque intent correlation. A missing or incomplete read does not authorize a second create. The default payment link requires an approved merchant page that runs Paddle.js. Local link expiry does not establish provider cancellation.
